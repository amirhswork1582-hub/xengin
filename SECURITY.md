# Security Policy

Xengin is designed to enforce rigorous security invariants (IDOR prevention, tenant isolation, input validation, and credential protection) during AI-assisted software engineering. We take any security vulnerabilities in Xengin or its workflows seriously.

---

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 0.3.x   | :white_check_mark: |
| < 0.3.0 | :x:                |

---

## Reporting a Vulnerability

If you discover a security vulnerability within Xengin:

1. **Do not open a public GitHub issue.**
2. Send a detailed report to the security team at `security@xengin.dev` (or via private GitHub Security Advisory).
3. Include:
   - A description of the vulnerability.
   - Steps to reproduce or a minimal proof of concept.
   - The potential impact on codebases or agent execution environments.

We will acknowledge receipt of your report within 48 hours and work with you to coordinate a responsible public release of the fix.
